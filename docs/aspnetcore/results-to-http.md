# Results to HTTP

A feature returns a `Result` ([results and errors](../core/results-and-errors.md)). The endpoint turns it into a response with `ToHttpResult()`. The return types are typed unions (`Results<Ok<T>, ProblemHttpResult>`), so **OpenAPI describes the endpoint's responses without any extra metadata**.

```csharp
return (await feature.HandleAsync(request, ct)).ToHttpResult();
```

## Overloads

| Call | Success | Failure |
|---|---|---|
| `Result<T>.ToHttpResult()` | `200 OK` with the value | problem |
| `Result<T>.ToHttpResult(value => …)` | whatever the function builds, for example `TypedResults.Created($"/posts/{value.Id}", value)` | problem |
| `Result.ToHttpResult()` | `204 No Content` | problem |
| `ApplicationError.ToHttpResult()` | | the problem for this error |
| `ValidationResult.ToHttpResult(error?)` | | the 400 validation problem with field details, or another error's code, message and kind |

```csharp
.ToHttpResult(post => TypedResults.Created($"/v1/posts/{post.Slug}", post))
```

## Kind to status

| `ErrorKind` | Status |
|---|---|
| `Validation` | 400 |
| `Unauthorized` | 401 |
| `Forbidden` | 403 |
| `NotFound` | 404 |
| `Conflict` | 409 |
| `Failure` | 500 |
| `Unavailable` | 503 |

## The problem body

`application/problem+json` (RFC 9457):

```json
{
  "status": 409,
  "title": "Conflict",
  "detail": "A post with this slug already exists.",
  "code": "post.slug_taken",
  "errors": { "slug": ["Already in use."] }
}
```

| Field | Value |
|---|---|
| `status`, `title` | From the kind. |
| `detail` | The error's `Message`. |
| `code` | The error's stable `Code`. **This is what clients branch on**, not the message. |
| `errors` | The error's `Details` (field path to messages), only when there are any. |

Problems generated by the pipeline itself (401, 403, 404, 405 without a body, 429, 500, an invalid idempotency key) use the same shape. A 500 never includes exception details.

## Documenting

Every endpoint already documents `401`, `403`, `429`, `500` and a `400` validation problem ([minimal endpoints](./minimal-endpoints.md#documented-problems)). Add the specific ones with `.ProducesProblem(404)` and the success type with `.Produces<T>()`, `.ProducesPage<T>()` or `.ProducesCursorPage<T>()`.
